# Context
Existing static Sudoku app in the current directory (plain HTML/CSS/ES modules, no build). Files: index.html, styles.css, src/{sudoku,game,storage,ui,main}.js, tests/sudoku.test.mjs, README.md, docs/PLAN.md. Core logic (sudoku.js, game.js, storage.js) is tested and should stay as-is unless needed. Live at https://brandon-schabel.github.io/sudoku-app/ (relative paths only).

# Problem
On an iPhone (393x852 CSS px Safari) the page scrolls: title, difficulty select + New Game, timer + Pause, Theme button stack on top, then the board, and mistakes/hints/number pad fall below the fold. The owner wants: top controls moved into a pause menu, board taking most of the screen, numbers + tools at the bottom, NO scrolling on mobile.

# Required redesign
1. Header: ONE slim bar only (<= ~48px tall on phones): optional small logo/title, timer (mm:ss), compact "Mistakes n/3" and hints count (icons or short labels OK), and an icon pause button on the right (aria-label "Pause"). Remove the old top controls (difficulty select, New Game, Pause, Theme button) from the main layout.
2. Pause menu: a modal sheet/overlay opened by the pause button, P / Space, or Escape (when no other modal is open). Contents: Resume (primary, autofocus), New Game with a difficulty picker (easy/medium/hard/expert; e.g. segmented buttons or select + button), Theme (auto/light/dark segmented, persisted as before), Restart current puzzle (resets values/notes/history/mistakes/hints/timer to the original puzzle; add a game.js method or rebuild state from puzzle+solution if simple), and a keyboard shortcut help section (collapsible OK). While open: game paused, timer stopped, board digits hidden/blurred. Escape or Resume closes it and resumes. Confirm before New Game/Restart when a game is in progress (a simple confirm step inside the sheet or window.confirm is fine). Accessible: role="dialog" aria-modal, focus trap, focus returns to board.
3. Board: square and as large as possible: side = min(available width, available height after header and bottom controls), centered. Use CSS (grid rows + container queries or min()/calc with dvh) — JS sizing is acceptable as a fallback only.
4. Bottom controls: a tool row (Undo, Erase, Notes toggle with obvious on/off state + aria-pressed, Hint, Redo) with inline SVG icons + small labels; then the number pad 1-9 in a SINGLE ROW on phones, each key showing remaining count, disabled when all 9 placed. Tap targets >= 44px tall. Remove the on-screen shortcut legend from the main layout (it lives in the pause menu now).
5. No scroll: html/body height 100dvh with 100vh fallback, overflow hidden on the app shell, layout as grid rows (header / board / controls), padding with env(safe-area-inset-*), add viewport-fit=cover to the viewport meta, overscroll-behavior: none, touch-action: manipulation, no text selection on controls. Must fit with NO vertical scroll at 375x667, 390x844, 393x852, 430x932, landscape phones (e.g. 844x390, 667x375) and desktop (1280x800, 1440x900). In landscape and on desktop (wide aspect), place the controls beside the board (board left, header-stats + tools + a 3x3 numpad right) with a sensible max width; on narrow portrait use the stacked layout.
6. Reload behavior change: when a saved game is restored on page load, resume it directly (running) instead of landing paused. Keep auto-pause when the tab is hidden; when the tab becomes visible again, show the pause menu (game remains paused until Resume).
7. Win and game-over modals keep working. Keep ALL existing features and keyboard shortcuts (1-9, Backspace/Delete/0/E erase, arrows, N notes, Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z / Ctrl+Y, H hint, P/Space pause, M theme cycle, Escape). Update README features/shortcuts.
8. Light and dark themes both look polished; keep the existing color variables.
